# 攻略分类与核验规范（E01-T02 / #10）

关联：[Issue #10](https://github.com/whyboy/hk-handbook/issues/10) · [Epic #8](https://github.com/whyboy/hk-handbook/issues/8)。

本规范供人工内容生产及页面设计使用，不定义生产 API 或数据库表。审核人批准规范不等于批准任何一篇攻略。

## 分类与标签

| 主分类 | 稳定标识 | 内容边界 | 主题补充字段 |
| --- | --- | --- | --- |
| 银行卡 | bank | 开户与账户使用资料 | 银行/产品、申请资格、材料、预约与费用条件 |
| 电话卡 | phone | 购买、实名与使用资料 | 运营商/套餐、实名条件、有效期、流量与续费条件 |
| 交通 | transport | 路线、票种与出行查询 | 交通方式、起终点或查询范围、服务时段、票价条件 |

每篇一个主分类，可有多个适用人群标签：游客、人才用户、家庭。
稳定标签标识为 `visitor`（游客）、`talent`（人才用户，含高才／优才相关情境）、`family`（家庭）。家庭可与其他标签同时使用；人才内容需在适用条件中写明具体计划及阶段。
人才标签表示内容相关性，不表示具备法定资格；游客/人才可重叠。所有筛选自选，阅读不要求登记身份。
关键词采用读者用语和常见同义词（如港铁/地铁）；禁止无证据的“必过”“最低价”等保证。
无适用内容的分类显示空状态，不能为了填满页面编造攻略。

## 字段与主题变体

复用 [TEMPLATE.md](TEMPLATE.md)。标题描述一个具体问题；摘要说明读完能解决什么。
每个资格、材料、费用、时效事实应指向来源编号和适用条件，不能只给全篇一个泛化链接。
不适用字段保留“不适用 + 原因”；未知信息写“待核验 + 阻塞发布”，不得以 0 元或无需材料代替未知。
银行、电话卡的资格/材料通常需要逐条核验；交通查询教程可以将申请材料标为不适用，但需说明查询准备。

## 信息类型

- 官方事实：记录发布机构、精确 URL、页面标题、适用情境、查阅日期、事实摘要和人工核验人。
- 个人经验：写明经历时间、具体机构/地点、条件与匿名化作者；不推导成统一规则，不能虚构亲历。
- 待核验：与事实分开；影响办理或费用决策的信息未核验前不得公开发布。
- 编辑建议：明确标注建议及理由，避免混写成官方要求。

## 人工工作流

资料收集 → AI 辅助草稿 → 人工逐条核验 → 编辑审核 → 人工发布 → 周期复核。
首次可用 Markdown 和 PR 完成，无需爬虫、AI 服务或内容后台。
作者记录出处，核验人实际打开来源并记录核验日期，审核人检查条件和措辞，发布人记录发布日期。
同一人兼任需明确记录，不能把 AI 检索记录当作人工签字；没有核验人和审核结论不能发布。
编辑时间随内容变化更新；事实核验日期仅在重新核对事实后更新，不能随格式编辑刷新。

## 更新、冲突与下架

内部建议复核周期：资格/费用/套餐每 30 天，查询教程每 90 天；这是编辑规则，不是官方有效期。
来源有明确失效日则在失效前复核。读者纠错、官方改版或政策变化立即触发复核。
到期标记“待复核”，停止推荐；关键条件不确定、来源失效或冲突未解决时先下架，保留文章 ID 与下架说明。
冲突需核对生效时间、地区、产品和对象，不以搜索排名或 AI 判断取代核验；无法消除冲突不发布关键结论。
修订记录包含旧值、新值、原因、来源、责任人与时间，重新审核后恢复；已有分享链接展示下架态而非无声重定向。

## 字段与页面对应

| 字段 | 编辑要求 | 页面用途 |
| --- | --- | --- |
| ID、版本、状态 | ID 稳定且不因改标题变化；每次实质修订递增版本 | 深链接、收藏及下架定位 |
| 标题、摘要、关键词 | 一个具体问题；摘要不重复空泛宣传；关键词可含同义词 | 列表、搜索、详情 |
| 主分类、适用标签 | 一个主分类，标签可多选；不作为资格判断 | 主题入口及组合筛选 |
| 适用条件、准备、步骤 | 不适用有理由，关键事实标来源编号 | 详情前置限制与操作正文 |
| 费用耗时、注意事项 | 币种、对象、生效范围；估计值不得包装成承诺 | 读者决策及异常处理 |
| 来源、核验记录 | 每条关键事实对应来源及人工记录 | 详情出处及核验日期 |
| 发布、编辑、核验日期 | 分开记录；未发生为“无”，禁止填当前日期代替 | 列表仅显示事实核验日期，详情分别显示 |

多条事实在不同日期核验时，保留逐条日期；文章级核验日期取所有仍有效关键事实中最早的核验日期，任何关键事实待核验时整篇不得标为“已核验”。这是首期人工编辑规则，后续可在评审后调整。

## 三类主题套用方式

以下仅演示字段结构，不陈述任何实际办理条件：

| 主题 | 必填补充内容 | 不适用／未知的表达 |
| --- | --- | --- |
| 某银行卡开户准备 | 银行与具体产品、申请渠道、申请对象、材料原件／副本、预约条件、费用触发条件 | 若未找到费用依据，写“待核验，阻塞发布”；不能写“免费开户” |
| 某电话卡实名与启用 | 运营商与套餐版本、适用证件、实名入口、启用步骤、有效期、用量与续费规则 | 如教程不涉及购买，说明购买价格不在范围；启用条件仍须核验 |
| 某交通工具路线查询 | 交通方式、查询范围、起终点输入、官方查询入口、时间与票价的适用条件 | 申请材料写“不适用：仅介绍查询”；没有固定票价应提供核实入口 |

## 状态与可见性

| 状态 | 进入条件 | 对外行为 |
| --- | --- | --- |
| 草稿／待核验 | 收集与 AI 整理阶段 | 仅内部评审，不进入公开列表、搜索或分享正文 |
| 待审核 | 关键事实已人工核验 | 等待审核人结论，不公开 |
| 已发布 | 审核通过，发布人留痕 | 可阅读、搜索、收藏及分享 |
| 待复核 | 周期到期或收到非关键疑点 | 停止推荐，仍可访问时显著提示待复核；不得宣称最新 |
| 已下架 | 关键事实不确定、冲突或失效 | 列表／搜索移除，稳定链接展示下架原因及返回入口 |

已有文章出现关键资格、材料或费用疑点时直接下架，不以“待复核”继续提供不确定的办理指引。复核通过需重新审核，记录修改与恢复时间。草稿的阅读示例必须显著标识未发布。

## 发布检查清单

可复制的逐项审核、责任签字及复核表见 [CHECKLIST.md](CHECKLIST.md)。


- [ ] 分类/人群/关键词与正文相符，不要求身份登记。
- [ ] 费用、资格、材料、时效逐条有来源和适用条件；不存在无依据承诺。
- [ ] 经验/建议与官方事实分开，未知或不适用字段说明原因。
- [ ] 来源可打开且无未解决冲突，事实人工核验人/日期已记录。
- [ ] 发布、编辑、核验日期分开，复核期限明确。
- [ ] 阅读、收藏、分享、纠错与下架状态经过评审。
- [ ] 人工审核结论和发布责任人齐全；AI 草稿未直接发布。
