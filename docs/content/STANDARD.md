# 攻略分类与核验规范（E01-T02 / #10）

## 分类与标签

| 主分类 | 稳定标识 | 内容边界 | 主题补充字段 |
| --- | --- | --- | --- |
| 银行卡 | bank | 开户与账户使用资料 | 银行/产品、申请资格、材料、预约与费用条件 |
| 电话卡 | phone | 购买、实名与使用资料 | 运营商/套餐、实名条件、有效期、流量与续费条件 |
| 交通 | transport | 路线、票种与出行查询 | 交通方式、起终点或查询范围、服务时段、票价条件 |

每篇一个主分类，可有多个适用人群标签：游客、人才用户、家庭。
人才标签表示内容相关性，不表示具备法定资格；游客/人才可重叠。所有筛选自选，阅读不要求登记身份。
关键词采用读者用语和常见同义词（如港铁/地铁）；禁止无证据的“必过”“最低价”等保证。
无适用内容的分类显示空状态，不能为了填满页面编造攻略。

## 字段与主题变体

复用 [TEMPLATE.md](TEMPLATE.md)。标题描述一个具体问题；摘要说明读完能解决什么。
每个资格、材料、费用、时效事实应指向来源编号和适用条件，不能只给全篇一个泛化链接。
不适用字段保留“不适用 + 原因”；未知信息写“待核验 + 阻塞发布”，不得以 0 元或无需材料代替未知。
银行、电话卡的资格/材料通常需要逐条核验；交通查询教程可以将申请材料标为不适用，但需说明查询准备。

## 信息类型

- 官方事实：记录发布机构、精确 URL、页面标题、适用情境、查阅日期、事实摘要和人工核验人。
- 个人经验：写明经历时间、具体机构/地点、条件与匿名化作者；不推导成统一规则，不能虚构亲历。
- 待核验：与事实分开；影响办理或费用决策的信息未核验前不得公开发布。
- 编辑建议：明确标注建议及理由，避免混写成官方要求。

## 人工工作流

资料收集 → AI 辅助草稿 → 人工逐条核验 → 编辑审核 → 人工发布 → 周期复核。
首次可用 Markdown 和 PR 完成，无需爬虫、AI 服务或内容后台。
作者记录出处，核验人实际打开来源并记录核验日期，审核人检查条件和措辞，发布人记录发布日期。
同一人兼任需明确记录，不能把 AI 检索记录当作人工签字；没有核验人和审核结论不能发布。
编辑时间随内容变化更新；事实核验日期仅在重新核对事实后更新，不能随格式编辑刷新。

## 更新、冲突与下架

内部建议复核周期：资格/费用/套餐每 30 天，查询教程每 90 天；这是编辑规则，不是官方有效期。
来源有明确失效日则在失效前复核。读者纠错、官方改版或政策变化立即触发复核。
到期标记“待复核”，停止推荐；关键条件不确定、来源失效或冲突未解决时先下架，保留文章 ID 与下架说明。
冲突需核对生效时间、地区、产品和对象，不以搜索排名或 AI 判断取代核验；无法消除冲突不发布关键结论。
修订记录包含旧值、新值、原因、来源、责任人与时间，重新审核后恢复；已有分享链接展示下架态而非无声重定向。

## 发布检查清单

- [ ] 分类/人群/关键词与正文相符，不要求身份登记。
- [ ] 费用、资格、材料、时效逐条有来源和适用条件；不存在无依据承诺。
- [ ] 经验/建议与官方事实分开，未知或不适用字段说明原因。
- [ ] 来源可打开且无未解决冲突，事实人工核验人/日期已记录。
- [ ] 发布、编辑、核验日期分开，复核期限明确。
- [ ] 阅读、收藏、分享、纠错与下架状态经过评审。
- [ ] 人工审核结论和发布责任人齐全；AI 草稿未直接发布。
