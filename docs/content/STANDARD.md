# 内容模型与发布核验规范

对应 [E02-T01 #10](https://github.com/whyboy/hk-handbook/issues/10)，父 [E02 #20](https://github.com/whyboy/hk-handbook/issues/20)。本目录交付内容契约与人工维护流程；运行时发布校验和 REST 查询归 #31，页面接入归 #32。模型通过不等于事实正确或允许发布。

## 维护入口

复制 [JSON 模板](template.json)，按 [字段契约](MODEL.md) 填写，逐项完成 [人工审核表](CHECKLIST.md)，以 PR 提交正文和核验记录。JSON 为内容唯一结构化源，Markdown 审核表保存签字和证据；不要维护第二份不同步的公开正文。不引入 CMS、爬虫、ORM 或额外数据库。

## 分类与人群

| category | 名称 | 边界与主题要求 |
| --- | --- | --- |
| bank | 银行卡 | 写明银行、产品、渠道、对象、材料及费用适用条件 |
| phone | 手机卡 | 写明运营商、套餐版本、实名、有效期及续费条件 |
| talent | 人才身份 | 写明高才／优才、路径与阶段，资格事实逐条核验；不在内容中执行初筛 |
| life | 生活落地 | 首次赴港准备、网络、交通；交通查询写明方式、查询范围与动态值核实入口 |

每篇一个分类；旧 `transport` 迁移为 `life`，ID 不变，不增加第五分类。人群 `visitor`（游客）、`talent`（人才用户）、`family`（家庭）可重叠，不是资格认定。关键词使用读者用语；没有内容显示空状态，不能编造文章填分类。

## 内容表达

每篇回答一个具体问题，按适用条件 → 准备／材料 → 步骤 → 费用耗时 → 注意事项阅读。主题字段不适用须给理由；未知与不适用分开，不用 0、空字符串或“无需”代替未知。银行和人才的资格、材料、费用、时间及例外都属于关键事实。

官方事实必须逐条映射来源及适用范围。个人经验必须标注经历时间、情境和匿名化作者，不推导为普遍规则；不得虚构亲历。编辑建议标注为建议；涉及事实时仍须指向事实账本。未知关键事实阻塞发布，不能移到“建议”段绕过核验。来源未注明生效时间用 `not_stated`，不能填查阅日期。

## 日期与责任

编辑日期记录文本修订，查阅日期记录实际读取来源，人工核验日期仅来自人工逐条核对，官方生效日期仅来自官方说明。四者独立；AI 只能填写自身查阅记录。未发生的审核、发布与核验使用 null，不预填当前日期或“已通过”。

人工核验记录绑定文章 revision 和事实 ID；审核与发布记录绑定同一 revision。任何正文、事实、来源、条件或关联修改均递增 revision，重新审核；格式修订也不能自行刷新事实核验日期。确实未变的事实可由人工在新版本审核中明确引用旧核验记录，不能自动继承。

复核期限由人工指定，不提供未经确认的统一 30／90 天默认值；必须有明确期限且不晚于已知来源失效日。到期当天停止公开正文（香港日期），不能仅修改编辑时间延长有效期。

## 发布决策：默认拒绝

以下规则为 #31 的实现契约与内容 PR 的人工检查要求。当前分支后端第一版已实现运行时校验与公开过滤，见 [E02-T03](../implementation/E02-T03.md)；是否已部署以发布记录为准。

1. JSON 结构、类型、枚举、长度、真实日历日期、ID 唯一性、引用完整性都有效；拒绝未知字段与重复 JSON 键，不能静默忽略拼写错误。
2. 仅 `published` 候选可公开。必须满足正文所有章节完整、无 unknown 章节、至少一个关键事实、每条事实和来源均有条件、引用及证据。
3. 每条关键事实都经真实人工核验为 passed；来源链接有人工有效性记录、无失效／未知／冲突，仍在复核期内。HTTP 200 或 AI 读取不能代替内容核对，重定向后的机构和页面也须核对。
4. 人工审核 approved、人工发布记录齐全，均针对当前 revision；签字人可兼任但注明原因。不能将 AI 或提交账户默认当作核验人。
5. 生效日已到，未超过失效范围；官方未注明有效期不伪造日期，但仍受人工复核期限约束。未来生效稿不能提前当作当前规则。`unknown` 有效期需核清是否官方未注明，不能直接发布。
6. 文章、事实、来源均未到复核截止日；出现来源冲突、关键条件疑点或失效链接，立即停止公开。未通过任意一项，不进入公开列表、搜索、首页推荐或正文详情。
7. 内部身份、核验笔记和证据文件不出现在公开 JSON；只投影正文、适用条件、来源的机构／标题／官方 URL、各日期和已开放的关联资源。不得放证件、收入、测评答案或私人资料。

人工签字的真实性只能人工确认。未来运行时结构校验不能证明签字真实，合并前必须核对 PR 中实际签字／证据；不得自动生成 passed。

## 状态与查询契约

| status／有效性 | 列表、搜索、首页 | 公开详情 |
| --- | --- | --- |
| draft、pending_review | 不出现 | 404，不泄露草稿标题或正文 |
| published 且所有门槛通过 | 可出现 | 200，仅公开字段 |
| published 但校验不合格 | 不出现 | 404；内部记录阻塞原因，不输出正文 |
| review_due，或 published 到达复核截止日 | 不出现 | 404，前端显示内容暂不可用 |
| withdrawn | 不出现 | 410，仅稳定 ID、通用下架说明和返回入口，不返回正文 |

未存在 ID 为 404；错误、空结果与下架不能混同。公开接口不得通过 preview 参数返回草稿；内部评审直接阅读 GitHub 文件，无需新增预览服务。列表／搜索／详情共用同一公开资格判断，先过滤再分页和计数，不泄露草稿数量。分类和人群取交集，关键词再与其取交集；分页、查询长度和错误响应由 #31 定义并测试，#32 使用相同分类与状态。

## 复核、下架与关联

纠错、官方变化、失效链接及来源冲突触发复核。人工在 PR 留下旧值、新值、原因、来源和责任记录；关键疑点先下架，不以免责声明继续提供不确定结论。保留 ID 与 Git 版本，恢复需再次核验、审核和发布。紧急下架的发布操作仍按维护者部署授权办理，本规范不授予部署权限。

银行、人才规则和清单关联只引用稳定资源 ID／版本，不复制条件或执行判断。目标不存在、未发布或未开放时不展示可执行按钮，不能因文章已发布就宣称目标可用。收藏归 E07，分享与统计归 E08。
