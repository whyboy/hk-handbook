# 港易通：产品方案

产品名：港易通。Slogan：第一次去香港，从这里开始。

## 产品定位

面向赴港办事、工作、生活的内地用户，以可核验指引和主题导航帮助用户了解要求、准备事项和下一步。首期免费，不做评论社区、支付订单、代办交易或自动爬虫。

按具体板块逐步开发：先确认某个板块的需求，再创建对应 Epic 和 Task，不预建全部远期业务。原“先完成银行匹配、人才初筛、清单三个核心工具”的统一实施顺序不再作为当前计划。

## 信息架构

底部保留首页、工具、攻略、我的四个 Tab。

| 页面 | 职责 |
| --- | --- |
| 首页 | 品牌、搜索、六个主题入口 |
| 工具 | 未来提供税率计算、香港薪资比较等独立小工具；具体模型、数据来源及维护方式在开发前确认 |
| 攻略 | 现有四分类、关键词及正文搜索、相关度排序、推荐与详情；不要求用户选择人群 |
| 我的 | 保留现有收藏／清单／记录框架，实际功能按后续板块需求确认 |

首页主题顺序固定，手机和桌面均为两行三列：

| 第一列 | 第二列 | 第三列 |
| --- | --- | --- |
| 港卡办理 | 高才／优才申请 | 电话卡办理 |
| 交通指南 | 景点推荐 | 税务指南 |

六主题替换原“办银行卡／申请身份／赴港清单”三个入口，移除“查看全部工具”。点击主题直接进入对应板块，不跳转工具页。首页内容入口只保留搜索和六主题。移除推荐攻略区域、查看全部攻略、我的收藏与记录按钮及页尾文案；攻略与个人记录仍通过底部 Tab 访问。首页不请求内容 API，后续以逐步扩展主题板块为主，不堆叠推荐流或重复入口。

首页主题是导航维度，不直接等于攻略分类。当前内容 category 仍为 bank / phone / talent / life，不为本次页面调整改写既有内容数据模型。未来主题内容与攻略关联在各板块开发时明确。

## 本次页面交付范围

六个主题分别提供独立页面：`pages/topics/bank`、`talent`、`phone`、`transport`、`attractions`、`tax`。页面保留对应标题、“内容整理中”与返回首页入口，支持直达和刷新。

当前不填充银行要求、申请条件、景点或税务事实，不提供评论、投票、匹配、测评或清单生成。空页面不展示有用／无用按钮及票数。本次保留工具 Tab 现有框架和旧二级路由，工具页的计算／比较能力另行设计实现；旧页面中的未来能力介绍不构成已排期需求。

## 后续具体板块的设计方向

港卡办理优先考虑通用流程与银行列表，再进入具体银行指引。具体银行、产品、身份、渠道的条件与材料必须分别核验，不能用通用清单暗示所有银行要求相同。银行匹配若有需要，可作为专题内辅助能力，不作为首页点击后的默认落点。

高才／优才在各自具体指引内区分路径、条件、材料和官方入口；不预设初筛引擎为首批必做。电话卡、交通、景点及税务各自按需求逐步补充。税务指引与税率计算器分别承担解释规则和计算的职责。

收藏、清单、分享、计算器、初筛及统计，在具体场景确认后再创建任务。历史设计可以参考，但不视为已授权开发或现有交付承诺。

## 内容反馈：有用／无用（后续实施）

具体指引将提供公开的“有用 N／无用 N”，不做评论区，不要求登录。按钮显示用户当前选择；再次点击取消，另一项改选，同一设备对同一指引版本只保留一票，重复点击不累计。请求失败恢复先前选择和票数，并提示重试。

票数必须来自后端真实统计，按指引及内容版本分开记录；版本更新不混入旧版票数。免登录设备标识不等于独立人数，也不能保证跨设备去重。存储、并发／重试幂等、公开读取和滥用控制在投票任务中设计，不以当前空页面伪装已实现服务。当前不收集文字原因或个人身份资料。

## 内容质量与搜索

正式攻略应说明适用条件、准备、步骤、费用时效、注意事项和官方来源。编辑、查阅、人工核验和生效日期分开；未审核、到期和下架内容不公开。港铁样稿仍待人工核验、真实查询及产品评审，代码合并不等于内容可发布。

搜索保留分类，匹配标题、关键词、摘要及正文，优先展示相关内容及匹配片段；无关键词展示编辑推荐。没有热度统计前不宣称热门排序。内容继续使用经审核的 JSON 包，暂无业务数据库内容管理系统。

## 验收与后续决策

本次验收：六宫格两行三列、名称和顺序正确、全部可达、返回正常、窄屏不溢出；首页搜索与四 Tab 正常，首页无攻略请求及已移除区域；空板块不伪造业务结果。H5 与微信小程序使用同一 src，构建与实际交互验收分别记录。

后续需逐板块确认：首批内容、来源与核验人、功能边界、维护周期、是否需要计算或清单、具体反馈服务契约。每次只为确认的范围创建 Epic／Task。税务和薪资工具的具体算法、统计样本、时间范围等尚未确认。
