# 港易通：香港落地小程序 MVP 产品与增长方案

产品暂定名：**港易通**。Slogan：**第一次去香港，从这里开始。**

本文描述港易通的目标用户、产品价值、MVP 范围、用户体验和验收标准。

## 1. 产品战略

面向所有有赴港办事、工作、生活需求的内地用户，提供“香港生活版的小红书攻略工具 + 办事导航 + 智能测评平台”。借鉴实用攻略的表达和发现方式，第一版不做社区。智能测评以可解释、可核验的规则初筛为核心，不预设引入生成式 AI。

核心价值：**查要求、比方案、做测评、生成清单**。用户从“我想去香港办什么”出发，知道适用条件、需要准备什么以及下一步去哪里核实和办理。

- 第一阶段：免费工具 + 实用内容，先把三个核心工具做得好用。
- 未来商业化方向：办理服务、合作转介、专业咨询。是否启动及具体方案另行确认，不纳入 MVP 支付、订单或收费功能。
- 总体增长策略：用高搜索需求的内容吸引用户，用工具促成使用，用清单和提醒创造复访。

优先场景为首次赴港办理银行卡、了解高才／优才申请条件、首次赴港生活准备。手机卡、网络和交通内容服务于这些办事流程，不扩展为独立交易平台。

## 2. MVP 范围与边界

三个核心工具是银行开户匹配器、人才资格初筛、赴港办事清单；其中人才初筛拆分高才与优才两个独立规则引擎。因此工具页可有四个入口，首页仍只突出三类任务。

| 范围 | MVP 产品要求 |
| --- | --- |
| 银行开户匹配 | 按用户情况比较公开条件，提供材料、费用、官方入口和注意事项 |
| 人才资格初筛 | 分开评估高才与优才，输出明确条件、待核验项和材料缺口 |
| 赴港办事清单（优先闭环） | 按目的生成清单，逐项打勾、收藏、复制和转发，再次打开继续准备 |
| 攻略与搜索 | 提供银行卡、手机卡、人才身份、生活落地内容，联通对应工具和清单 |
| 我的 | 我的收藏、办事清单、测评记录、反馈 |
| 来源与质量 | 关键事实可追溯、可核实；过期或缺失信息明确提示 |

MVP 不包含社区发帖、评论、关注、私信、支付订单、代办交易、自动爬虫或跨设备同步。内容由人工维护和审核；MVP 不要求独立内容管理后台。

阅读、搜索和分享无需登录，收藏保存在本设备。清单进度与测评记录以本设备保存为首期设计基线，需在详细设计明确保存范围、清除入口和设备／浏览器间不互通的提示。提醒先体现为清单内的出发前核实提示；主动订阅消息的授权、频率和送达机制留待确认，不纳入首期主动推送范围。

## 3. 三个核心工具

### 3.1 银行开户匹配器

输入包括是否持有香港身份证、开户用途、能否亲临香港、是否需要跨境服务；允许“不确定”，避免将未知信息当成不符合条件。

结果展示适合进一步了解的银行，并按统一维度列出匹配理由、未满足或待核实条件、所需证明文件、常见费用及适用条件、官方链接、开户前注意事项。没有匹配结果时说明原因，提供修改条件或官方查询入口，不虚构推荐。

每条银行信息维护适用对象、来源、生效日期、最后核实时间和维护状态。官方未明确生效日期时标注“官方未注明”，不得用编辑日期补齐。信息过期或来源失效时提示重新核实，不能继续呈现为已确认条件。

“可能符合公开开户要求”不等于“保证开户成功”；最终以银行审核为准。不将推荐顺序包装为成功率，不在本文件指定未经核验的银行、费用或开户门槛。

### 3.2 高才与优才初筛

两套规则分别维护来源、版本、生效日期和核实时间，不能共用一个含混的分数或判定结果。

- 高才：分别覆盖 A、B、C 三类申请路径；根据相关收入、学历、毕业时间、工作经历等条件引导输入，具体字段与阈值以核验后的官方规则为准。
- 优才：先检查基本资格，再区分综合计分制和成就计分制；综合计分制按官方多项评核准则逐项呈现，不沿用未经核验的历史计分表。

统一输出：初步符合哪些明确条件、哪些条件暂不符合、哪些信息仍需人工或官方文件核实、缺少哪些证明材料、官方最新申请入口，以及本次采用的规则版本和核实日期。用户可修改输入重新初筛，并从结果生成对应材料清单。

“不确定／信息不足”应保留为待核实，不得默认为通过或不通过。不输出没有可靠统计依据的“预计通过率 90%”，不将初筛结果表述为官方资格认定或批准承诺。

官方规则来源：

- [入境事务处：高端人才通行证计划常见问题](https://www.immd.gov.hk/hks/faq/TTPS.html)。
- [入境事务处：优秀人才入境计划](https://www.immd.gov.hk/hks/services/visas/quality_migrant_admission_scheme.html)。

申请入口应从官方页面核实并维护。规则上线前还需人工逐条核对条件、例外、材料及生效时间。产品不收集证件扫描件，不代用户提交申请。

### 3.3 赴港办事清单：优先完成的核心闭环

清单把内容和测评转化为实际准备动作，是本项目最优先验证的产品价值。用户选择赴港目的，可直接生成模板清单，也可从银行匹配／人才初筛结果生成对应清单。

“首次赴港办理银行卡”模板至少覆盖以下六个阶段；这里是信息结构示例，具体材料和银行要求需后续核验：

1. 出发前确认资料：核对目的、适用条件及仍需确认的要求。
2. 准备所需证明文件：根据目标银行和用户情境列出材料与缺口。
3. 核实预约及银行营业安排：提供官方查询入口，提示出发前再次确认。
4. 香港电话卡和网络准备：关联适用攻略，确认办事期间通信方式。
5. 前往网点的交通安排：关联路线查询信息，提醒确认实际地址及当日安排。
6. 完成后的注意事项：按银行官方说明检查后续操作和仍待处理事项。

每个步骤都能打勾／取消打勾、收藏、复制和转发；整份清单也可保存并再次打开继续使用。步骤需说明做什么、何时做、依据或相关攻略，以及待核实事项；不同赴港目的对应不同模板，不能只替换标题。

保存、复制或分享失败应明确反馈，不显示虚假成功；缺失或下架模板提供返回与重新选择入口。模板更新时提示用户核对变化，不静默覆盖已完成进度。

分享默认使用不含个人输入和完成状态的模板／步骤内容，接收者建立自己的清单，不修改发送者进度。微信使用原生转发，H5 至少提供复制文本或链接；两个平台均需反馈操作结果。个人收入、身份和测评答案不得进入公开分享链接。

## 4. 信息架构与首页方向

底部固定四个 Tab：**首页、工具、攻略、我的**。专题和详情在二级页面，不在首页并列十几个功能。以下为页面职责与建议路由。

| 层级／页面 | 建议路径 | 内容与职责 |
| --- | --- | --- |
| 首页 | `pages/index` | 快捷搜索、三类核心工具、精选专题、热门／最新攻略 |
| 工具 | `pages/tools/index` | 银行开户匹配、高才资格初筛、优才资格初筛、清单生成 |
| 攻略 | `pages/guides/index` | 银行卡、手机卡、人才身份、生活落地；交通作为生活落地及办事流程内容 |
| 我的 | `pages/profile/index` | 我的收藏、办事清单、测评记录、反馈 |
| 攻略详情 | `pages/guides/detail` | 正文、适用条件、来源、核实日期及关联工具／清单 |
| 工具结果 | `pages/tools/result` | 匹配／初筛解释、待核实项、材料缺口、生成清单入口 |
| 清单详情 | `pages/checklist/detail` | 分阶段步骤、进度、收藏、复制和转发 |

首页布局如下，示例文章标题用于表达内容方向：

```text
港易通                         （品牌区）
第一次去香港，从这里开始。
[搜索：香港银行卡 / 高才 / 手机卡]
首次来港 · 免费实用工具
你来香港，准备办什么？
[办银行卡]       [申请身份]       [赴港清单]
热门攻略／精选专题（控制数量，更多内容进入二级页）
[银行开户攻略：适用人群、摘要、核实日期]
[高才通 A/B/C 类资格说明]
[第一次赴港必备办事清单]
[首页]           [工具]           [攻略]           [我的]
```

“申请身份”先选择高才或优才，再进入对应初筛。MVP 不要求定位权限或附近推荐。攻略标题年份仅在内容核实和持续维护后使用，不因年份较新而暗示已核实。

公共详情页支持单页分享、参数化进入、来源渠道识别和浏览统计。参数只携带必要的内容／模板标识、工具类型及非敏感来源信息；私人测评结果不通过公开 URL 暴露。直接进入详情时提供返回首页／相关列表入口。需覆盖无搜索结果、空收藏、空记录、加载失败、内容下架和规则待核实等状态。

## 5. 关键用户旅程

| 用户目的 | 产品闭环 |
| --- | --- |
| 首次赴港开户 | 搜索／分享进入攻略 → 银行匹配 → 比较公开要求 → 生成清单 → 准备与勾选 → 再次打开继续核实 |
| 了解人才申请路径 | 人才攻略／申请身份入口 → 选择高才或优才 → 初筛 → 查看明确条件与材料缺口 → 生成清单 → 官方入口核实 |
| 首次赴港生活准备 | 直接选择赴港目的 → 模板清单 → 手机卡／网络／交通攻略 → 收藏或复制步骤 → 回到清单推进 |

内容页要给用户明确下一步；工具结果要能落到清单；“我的”要能找回进度。阅读攻略、查看官方来源不强制先做测评。

## 6. 内容与增长方案

围绕银行卡、人才身份、手机卡和首次赴港准备等搜索需求制作实用内容。每篇攻略回答一个具体问题，说明适用对象、条件、材料、步骤、费用适用范围、注意事项和来源；关键事实经过人工核验后才能公开发布。

获客入口为微信搜一搜、微信分享和内容渠道。分享落到对应攻略、工具说明或清单模板；用户随后完成匹配／初筛或生成清单。保存的清单、未完成事项及出发前核实提示构成复访理由。主动提醒作为后续待确认能力，不以频繁推送替代实际价值。

以下指标用于验证增长假设；先建立基线，再约定统计窗口与目标值：

| 观察目标 | 建议指标口径 |
| --- | --- |
| 内容带来工具使用 | 从攻略进入工具的去重用户数 / 攻略阅读去重用户数 |
| 工具可完成 | 获得有效匹配或初筛结果的用户数 / 开始对应工具的用户数 |
| 结果转化为行动 | 从结果生成清单的用户数 / 查看对应结果的用户数 |
| 清单产生实际使用 | 至少完成一个步骤的用户数 / 生成清单的用户数 |
| 清单创造复访 | 生成后 7 日内再次打开清单的用户数 / 已满 7 日观察期的清单生成用户数 |
| 内容可信且有效 | 关键事实来源覆盖情况、过期条目数、纠错处理情况 |

免登录设备口径不能等同于真实自然人或跨设备留存；统计只记录必要行为和渠道，不采集测评答案、收入、证件等敏感内容。商业化验证放在核心工具与清单价值验证之后，合作转介如后续启动需明确披露，不改变公开条件的客观表述。

## 7. MVP 产品验收标准

- 首页、工具、攻略、我的四个 Tab 层级清楚，核心任务与异常状态可理解。
- 攻略标明适用条件、来源、生效／核实时间，关键事实经过人工审核。
- 清单按赴港目的生成；开户模板覆盖六个阶段，支持步骤级勾选、收藏、复制、转发及保存后继续使用。
- 银行匹配展示可解释结果、统一比较维度、官方入口，以及未知或无匹配状态。
- 高才与优才分别使用可追溯规则，解释明确条件、待核实事项和材料缺口，不输出虚构通过率。
- 攻略、工具结果、清单和我的形成连续使用路径，分享内容与个人数据边界清楚。
- H5 与微信小程序的核心路径可用，平台差异有明确反馈；产品体验与内容准确性通过评审。

## 8. 后续需明确的产品决策

- 首批银行、各场景内容与模板覆盖清单，以及维护人与核验频率。
- 两套人才规则的逐条来源、例外和版本更新流程。
- 本设备保存的具体字段、保留期限与清除交互；跨设备同步不属首期。
- 提醒是否启用订阅消息，以及用户授权、触发时机和频次。
- 统计窗口、目标值、正式名称与视觉规范。

产品支持 H5 与微信小程序，两端保持一致的信息架构和核心流程。
