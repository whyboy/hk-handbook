# E01-T01：首页框架

对应 [Task #9](https://github.com/whyboy/hk-handbook/issues/9)，属于 E01 页面框架。本阶段只交付首页与必要的导航承接，不实现搜索、开户匹配、人才初筛、清单生成、收藏或反馈业务。

> 后续 T02 已扩展工具列表与结果空状态，申请身份入口可分别选择高才和优才。当前行为见 [E01-T02](E01-T02.md)，下文保留 T01 交付范围。

## 查看方式

```bash
cd frontend
npm ci
npm run dev:h5
```

打开终端显示的本地地址。首页为 `/pages/index/index`；H5 使用 hash 路由，可直接访问 `/#/pages/tools/intro?scene=bank` 验证说明页及返回行为。

微信小程序执行 `npm run build:mp-weixin`，在微信开发者工具中导入 `frontend/dist/build/mp-weixin`；AppID 仍需由开发者配置。构建不需要 AppID，不代表已完成真机验收。

## 展示与交互

- 首页依次展示品牌、Slogan、搜索外观、三类任务入口及示例攻略卡片。
- 搜索仅提示“搜索功能建设中”，不收集搜索词，不查询服务。
- 办银行卡、申请身份、赴港清单分别打开用途说明，统一提示“功能建设中”。
- 攻略卡片标注“示例 · 尚未核验”；点击只提示内容未开放，没有编造正文、银行推荐或资格结论。
- 说明页支持返回首页；直接进入或刷新页面后没有页面栈时，重新打开首页。缺失或无效场景显示不可用说明，并保留返回入口。

## 路由与实现边界

| 页面 | 路径与参数 | 职责 |
| --- | --- | --- |
| 首页 | `/pages/index/index` | 静态内容展示、未开放提示和三个入口 |
| 工具说明承接页 | `/pages/tools/intro?scene=bank`、`identity`、`checklist` | 对应任务用途、未开放状态及返回首页 |

静态视图模型位于 `frontend/src/features/home/content.ts`；导航路径和跳转集中在 `frontend/src/navigation/index.ts`，使用 uni-app API，不依赖浏览器 DOM 或后端接口。参数按允许的场景查找，不将任意 URL 参数当作工具配置。

按任务编码顺序串行交付：T01 先注册自身所需的两个页面和最小导航；T02 扩展工具页与说明框架；T03、T04 分别交付攻略及我的页面；T05 再统一四 Tab 和公共导航。当前不展示尚未交付的底部 Tab，也不以占位页面冒充后续 Task 已完成。

每个 Task 只提交一个实现 PR，当前 PR 合并前不开始下一个 Task。README 的运行命令保持不变。

## 人工评审路径

1. 在窄屏和桌面宽度查看首页，核对内容顺序、示例标识与可读性。
2. 点击搜索和三张攻略卡片，确认只有未开放提示。
3. 依次点击三个任务入口，核对说明与标题，点击“返回首页”。
4. 直接打开或刷新说明页，确认仍能返回首页；将场景改成未知值或移除参数，确认有不可用说明。
5. 微信开发者工具和真机重复上述路径，核对原生导航、点击反馈、字体及安全区。

实际自动验证见 [验证记录](../VALIDATION.md)。产品负责人评审和微信真机验收仍待执行，不因 PR 创建而标记通过。
